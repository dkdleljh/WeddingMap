# 운영 가이드

## 1. 운영 목표
- 예식장 데이터의 신뢰도를 유지합니다.
- 수집 로그와 관리자 검수를 통해 데이터 품질 문제를 빠르게 찾습니다.
- 사용자 문의와 리뷰 처리 지연을 최소화합니다.

## 2. 일일 운영 체크리스트
- 대시보드에서 등록 예식장 수와 운영 중 예식장 수 확인
- 미검수 리뷰 수 확인
- 문의 대기 건수 확인
- 최근 수집 로그 성공 여부 확인
- 감사 로그에서 비정상 대량 수정 여부 확인
- 오류 로그와 비정상 로그인 시도 점검

## 3. 예식장 데이터 운영 원칙
- 주소, 전화번호, 홈페이지는 기본 식별 정보로 우선 검수합니다.
- 가격과 식대는 검수 시점과 함께 관리합니다.
- 공공예식장 여부는 원천 출처와 운영 조건을 함께 기준으로 판단합니다.
- 데이터 신뢰도 등급은 A, B, C, D로 구분하고 변경 이력을 남깁니다.

## 4. 리뷰 운영 원칙
- 광고성 리뷰, 욕설, 허위 의심 리뷰는 숨김 처리합니다.
- 실제 방문 또는 계약 근거가 있는 리뷰는 우선 승인합니다.
- 리뷰 수가 적은 예식장은 평점보다 리뷰 신뢰도 보정값을 함께 봅니다.

## 5. 문의 운영 원칙
- 접수됨
  - 아직 담당자가 확인하지 않은 상태
- 처리 중
  - 운영자가 응답 준비 또는 전달 중인 상태
- 처리 완료
  - 사용자 응답까지 마친 상태

## 6. 수집 실패 대응
- 공공데이터포털 URL 오류 여부 확인
- 인증키 만료 또는 오입력 여부 확인
- 응답 형식이 JSON인지 확인
- 원천 필드명이 변경되었는지 확인
- 병합 요약에서 중복 후보가 급증했는지 확인

## 7. 장애 대응 절차
### API 장애
1. `/health` 응답 확인
2. 데이터베이스 연결 설정 확인
3. 최근 배포 변경점 확인

### 웹 장애
1. API 응답 여부 확인
2. 환경 변수 확인
3. 빌드 산출물 재생성

### 수집기 장애
1. 공공데이터포털 응답 구조 확인
2. 파서 테스트 재실행
3. 운영자 수동 업로드 경로로 임시 대체

## 8. 정기 점검 항목
- 의존성 보안 공지 확인
- Next.js 보안 패치 적용 여부 확인
- JWT 비밀키와 외부 API 키 교체 주기 확인
- 오래된 문의와 미검수 리뷰 적체 여부 확인
- 관리자 계정 활성 상태와 권한 변경 이력 확인

## 9. 운영 전 최종 검증 명령
- 로컬 출고 전에는 아래 명령으로 전체 테스트와 빌드를 함께 검증합니다.

```bash
npm run verify
```

- API만 빠르게 확인할 때는 다음 명령을 사용합니다.

```bash
npm run dev:api
```

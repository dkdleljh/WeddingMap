# 테스트 가이드

## 1. 테스트 목적
WeddingMap의 테스트는 화면 렌더링 확인만이 아니라, 예산 계산, 점수 계산, 수집 파싱처럼 제품 핵심 의사결정 로직이 깨지지 않도록 막는 데 목적이 있습니다.

## 2. 현재 포함된 테스트
### 백엔드와 수집기
- 예산 계산 로직 테스트
- 종합 점수 계산 테스트
- 공공데이터 수집 파서 테스트

### 사용자 앱
- 카드 렌더링 테스트
- 예산 계산기 계산 유틸 테스트

### 관리자 앱
- 대시보드 렌더링 테스트

## 3. 실행 방법
### 전체 테스트
```bash
./scripts/test_all.sh
```

### 백엔드만 실행
```bash
source apps/api/.venv/bin/activate
PYTHONPATH=apps/api python -m pytest tests/api tests/ingestion
```

### 사용자 앱 테스트만 실행
```bash
npm run test:web
```

### 관리자 앱 테스트만 실행
```bash
npm run test:admin
```

## 4. 최근 점검 결과
- 백엔드와 수집기 테스트 통과
- 사용자 앱 Vitest 통과
- 관리자 앱 Vitest 통과
- 사용자 앱 빌드 통과
- 관리자 앱 빌드 통과

## 5. 테스트 설계 원칙
- 예산 계산과 점수 계산은 숫자 규칙이 바뀌어도 추적 가능해야 합니다.
- 수집 파서는 실제 공공데이터 응답 구조를 흉내 낸 테스트 입력을 가져야 합니다.
- 화면 테스트는 너무 세밀한 마크업보다 핵심 문구와 핵심 상호작용 중심으로 유지합니다.
- 관리자 화면은 승인, 숨김, 상태 변경 같은 운영 액션의 연결을 우선 검증합니다.

## 6. 권장 추가 테스트
- 관리자 수정 후 AuditLog 생성 테스트
- 예식장 필터 조합 검색 API 테스트
- 비교함 최대 5개 제한 테스트
- 로그인 실패와 권한 분리 테스트
- 수집기 `portal` 모드의 HTTP 응답 모킹 테스트
- 공공예식장 분류 규칙 테스트

## 7. 운영 배포 전 체크리스트
- `pytest` 통과 여부
- `npm run test:web` 통과 여부
- `npm run test:admin` 통과 여부
- `npm run build:web` 통과 여부
- `npm run build:admin` 통과 여부
- API 서버 `/health` 응답 확인
